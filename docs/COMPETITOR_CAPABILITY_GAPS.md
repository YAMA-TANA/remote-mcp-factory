# PicoSvc: competitor capability gaps (feature scope, not a ranking)

Reviewed: **2026-09-21**. This supplements [pricing benchmarks](PRICING_BENCHMARKS.md), the [launch handoff](PICOSVC_LAUNCH_HANDOFF.md), and the user-facing comparison in each service's workspace. The seven vendor pages below were opened and checked against the corresponding comparison text in `web/app/customer-content.ts`. The other nine in-workspace comparisons retain the sources introduced by the earlier comparison work. **Do not infer that a source-level feature is deployed, that a competitor feature is included in every plan, or that prices and SLA/performance are equivalent.** Vendor capabilities and prices may change; recheck the linked pages before publication.

| PicoSvc service | Vendor source and documented scope | PicoSvc source-level scope / distinction | Honest next acceptance or development step |

| MCP | [Smithery — publishing](https://smithery.ai/docs/build) documents server discovery, client connection, distribution, usage analytics and gateway behavior. | GitHub-source MCP deployment and connection URL, with build/runtime status and scoped metrics; a hosting workflow is not the same as a distribution marketplace. | Verify actual GitHub → build → Edge/Sandbox → MCP-client connection and token isolation. No live receipt guarantee before that. |
| QR | [Bitly QR Codes](https://bitly.com/pages/products/qr-codes) documents editable QR destinations, styled codes, detailed scan analytics and location/device routing. | PicoSvc provides editable redirect URLs and SVG QR, with bounded scan usage; the product guide explicitly excludes advanced geo/device routing and marketing analytics. | Check a real scan → redirect → aggregate workflow; do not suggest that basic scan totals equal Bitly's segmentation, styling or unlimited scans. |
| Cron | [Upstash QStash schedules](https://upstash.com/docs/qstash/features/schedules) documents cron-based scheduled HTTP publishing and timezones; [QStash retry](https://upstash.com/docs/qstash/features/retry) documents message retry behavior. | PicoSvc supports HTTP methods, cron scheduling, run/attempt history, bounded retries and optional failure webhook. Correct the older UTC-only customer-copy wording to reflect the separately configured timezone before relying on it as a complete guide. |
| Functions | [Vercel Functions](https://vercel.com/docs/functions) documents framework-integrated server-side functions, managed scaling and runtime options. | PicoSvc provides a small JavaScript HTTP-handler service; arbitrary npm packages and long-running workloads are out of scope. | Verify CPU/runtime and external subrequest ceilings in deployed Dynamic Workers, logs and rollback before marketing it as a general serverless alternative. |
| Monitor | [UptimeRobot website monitoring](https://uptimerobot.com/website-monitoring/) documents website availability checks, alerts and public status pages. | PicoSvc records page-content changes and fetch errors; it is not an uptime SLA, multi-region availability monitor or status-page service. These are different monitoring jobs, not directly interchangeable products. | Verify scheduled change detection, error classification, notification delivery and cleanup on the deployed Worker. Avoid comparing an hourly content check with a minute-level availability check as equivalent. |

## Comparison publishing guardrails

1. Always show *both* the PicoSvc behavior and the vendor's documented behavior, link the exact vendor source and show PicoSvc limitations nearby. A missing feature is not evidence that a competitor is worse, or vice versa.
2. Keep source-level API, provider configuration, signed-in browser acceptance, and production deployment as separate checkboxes. In particular, a successful TypeScript build does **not** prove Browser Run, Email Routing, live billing or DNS.
3. Treat pricing comparisons separately: plan availability, unit (per service vs. bundle), monthly vs. annual billing, included capacity, overages and checkout currency must be comparable before publishing a numeric claim. [Existing benchmarks](PRICING_BENCHMARKS.md) are dated 2026-09-16 and should be reverified before promotional use.
4. The in-workspace competitor map and `scripts/test-picosvc-management-guidance.mjs` now require official-source links and localized capability comparisons for **all 16 services**. Regression tests validate static wiring, not whether vendor webpages will remain unchanged.
